# ADR-0001：各平台原生实现，共享规格而不共享代码

- 状态：已采纳
- 日期：2026-09-28

## 背景

QuietChat 先支持 macOS，之后要支持 Windows。它的核心能力都依赖各平台自己的系统接口：跟踪另一个应用的窗口、在它上方显示遮罩、模拟按键、截图与 OCR。界面反而很少，只有菜单栏菜单、遮罩和一个小设置页。

## 决策

- 每个平台用原生技术单独实现：macOS 用 Swift + AppKit；Windows 计划用 C# + .NET + WPF。
- 两端共享**规格**，不共享**代码**：
  - `docs/architecture.md` 定义模块划分和行为规则；
  - `shared/` 存放配置格式和测试样本，两端的测试都以它们为准。
- 两端的纯逻辑层（macOS 为 `QuietChatCore`，Windows 为 `QuietChat.Core`）保持同样的职责和类型命名，方便对照着移植和修 bug。

## 否决的方案

- **Electron / Tauri / Flutter**：只能帮上设置界面。窗口跟踪、遮罩、按键模拟、OCR 仍然要给每个平台写原生插件，框架带来的体积和复杂度得不偿失。
- **Rust 共享核心 + 各平台原生外壳**：目前纯逻辑只有几百行，引入 FFI 和双平台构建链的成本高于写两份。

## 影响

- 纯逻辑要用 Swift 和 C# 各写一份，一致性靠共享规格、配置 schema 和测试样本保证。
- 如果以后纯逻辑明显变复杂（例如识别策略需要多个识别器投票），再评估抽出 Rust 共享核心。模块边界已经划好，到时迁移的成本可控。
