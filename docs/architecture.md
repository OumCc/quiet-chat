# QuietChat 架构说明

> **摘要**：QuietChat 在微信电脑版窗口上方放一块遮罩，盖住聊天列表；输入密码才能看到全部聊天，关掉微信窗口后自动重新锁定。遮挡方式有两种：整块遮住，或者只露出白名单里的聊天（精准遮挡）。macOS 和 Windows 各用原生技术实现，共享本文定义的模块划分与行为规则，以及 `shared/` 下的配置格式。v1 分 M0–M2 三个阶段交付，v2 增加精准遮挡，每个阶段在真实环境验收通过后再进入下一阶段。

## 1. 目标与边界

- **目标**：打开微信时，不让无关的聊天、公众号先抢走注意力。定位是"加一点阻力"，不是安全锁。
- **v1 范围**：整块遮住聊天列表；输入密码解锁；关闭微信窗口后自动锁定。
- **v2 范围**：精准遮挡，锁定时只露出白名单聊天所在的行。
- **不做**：注入或修改微信进程，联网，保存或上传画面。整块遮挡不读取任何聊天内容；精准遮挡只读取聊天列表区域的画面，在本机内存中识别聊天名称。
- **可以接受的绕过**：⌘F 搜索、点通知跳转、独立聊天窗口、通讯录、直接退出 QuietChat、锁定时先恢复默认密码再解锁。

## 2. 已验证的前提

| 结论 | 依据 | 影响 |
|---|---|---|
| 微信 4.x 界面基于 Qt（窗口类 `QNSWindow`）。辅助功能接口只暴露窗口本身和三个窗口按钮，读不到聊天列表 | Accessibility Inspector 检查（微信 4.1） | 窗口位置和事件用辅助功能接口获取；列表内容只能靠截图识别（v2） |
| 不需要任何权限，窗口服务器（CGWindowList）就能读到微信各窗口的外框、层级和是否在屏。微信进程同时有十来个 layer 0 窗口（提示框、条状辅助窗口等） | 本机实测 | 主窗口要靠辅助功能接口识别 |
| 转发等弹窗是微信单独的 layer 0 窗口，压在主窗口之上，但不在辅助功能窗口列表里；弹出时主窗口变暗由主窗口自己绘制，没有单独的蒙层窗口。主窗口显示时，微信的辅助窗口都不在屏。右键菜单在 layer 21，本来就高于遮罩 | 本机实测（微信 4.1） | 微信自己的窗口也当作遮挡、开洞让出；弹窗只能靠窗口服务器识别 |
| Apple Vision OCR 能认出列表里的聊天名称（真实深色截图 6/6）。置顶行和普通行的底色可以区分（`#3B3B3E` / `#2F2F30`） | `tools/probe/wechat_list_probe.swift` | v2 的精准遮挡可行 |
| 用 ScreenCaptureKit 持续截取单个窗口时，系统会把该窗口的红绿灯换成紫色的共享标记；每 0.1 秒取一张静帧则没有标记，菜单栏也没有录屏指示。`sourceRect` 对单窗口过滤器生效，取到的就是裁剪后的区域 | `tools/probe/wechat_capture_probe.swift`（macOS 26.5） | 精准遮挡用定时取静帧读取画面，不开持续的截图流 |
| 微信 4.1 深色模式：悬停让行底色的亮度升高 5～11；选中行是绿色 `#2EAA6A`，亮度比普通行高约 70。行距 65 pt。截断名称末尾的"…"会被文字识别读成 `..`、`.`、`⋯` 等写法 | 同上 | 变化检测要容忍小幅的底色变化；选中按内容变化处理；省略号的判定要覆盖这些写法 |
| ScreenCaptureKit 报告的窗口位置（`SCWindow.frame`）出现过与实际位置不符的情况 | 同上 | 几何信息一律以窗口服务器为准 |

## 3. 平台策略

各平台原生实现，不用跨平台 UI 框架，理由见 [ADR-0001](adr/0001-native-per-platform.md)。两端共享：

- **模块划分与行为规则**：本文第 5、6 节。两端使用相同的模块名和语义。
- **配置格式**：`shared/config.schema.json`。两端的测试都要校验自己的配置模型与它一致。
- **测试样本**：真实截图里有聊天名称和消息预览，不放进仓库。识别流程的测试用程序画出来的合成列表图片。

## 5. 模块

| 模块 | 职责 | macOS | Windows（规划） |
|---|---|---|---|
| Core | 纯逻辑：坐标换算、列表栏布局、遮罩决策、主窗口挑选、配置模型，以及精准遮挡的名称匹配、行切分、变化检测。不依赖界面和系统接口 | `QuietChatCore`（SwiftPM） | `QuietChat.Core`（.NET 类库） |
| WindowTracking | 找到微信主窗口，产出 `WindowSnapshot`；窗口可能变化时触发刷新 | 辅助功能（AXObserver）+ CGWindowList | SetWinEventHook + DWM 窗口外框 |
| Masking | 按 `MaskDecision` 显示、移动或收起遮罩；校准 | 不激活本应用的浮动 NSPanel | 置顶的分层窗口 |
| Lock（M2） | 锁定状态、密码校验、自动锁定 | Core 的 `LockState`、`PasswordVerifier`（CommonCrypto），遮罩上的密码框 | 同样的 Core 类型，`Rfc2898DeriveBytes.Pbkdf2` |
| Capture（v2） | 定时读取微信主窗口里聊天列表区域的画面，判断内容有没有变化 | ScreenCaptureKit（`SCScreenshotManager` 定时取静帧） | Windows.Graphics.Capture |
| Detection（v2） | 识别画面里的文字，交给 Core 切分成行、与白名单匹配 | `QuietChatDetection`（Vision） | Windows.Media.Ocr |
| App | 菜单栏（托盘）、权限引导、读写配置、白名单编辑、组装各模块 | NSStatusItem | NotifyIcon |

模块之间只通过 Core 定义的值类型交换数据：WindowTracking 产出 `WindowSnapshot`，Masking 执行 `MaskPlanner.decide` 返回的 `MaskDecision`。精准遮挡时，Capture 和 Detection 得出要露出的带区，同样交给 `MaskPlanner`。

## 6. 行为规则

### 6.1 遮罩几何

- 列表栏矩形：窗口外框左上角偏移 (`leftInset`, `topInset`)，宽 `width`，向下延伸到窗口底边，结果裁剪到窗口内。
- 其他普通窗口（层级 0、可见）压在微信主窗口之上时，把它和列表栏重叠的部分从遮罩上挖掉（开洞），让给上层窗口。微信自己的窗口（转发等弹窗、独立聊天窗口）同样开洞。
- 精准遮挡下，识别为白名单聊天的行同样开洞（见 6.6）。遮罩底部 56 pt 的一条始终遮住，密码框放在这里，白名单行落在这一条里的部分不开洞。
- 遮罩和洞一律向外取整到整点，校准结果也取整。小数坐标会在边缘留下半透明像素，看起来是一条细线，而且会挡住点击。
- 总原则：**宁可多遮，不漏出**。

### 6.2 显示规则

| 微信主窗口 | 遮罩 |
|---|---|
| 在当前桌面可见 | 显示在列表栏上 |
| 最小化、微信被隐藏或退出 | 收起 |
| 不在当前桌面，遮罩在当前桌面 | 收起（窗口被关闭或移走了） |
| 不在当前桌面，遮罩也不在当前桌面 | 保持不动（两者都在另一个桌面，切回去时一起出现） |

遮罩始终处于浮动层级，所以微信被点到最前时也盖不过它。

桌面归属：
- 微信主窗口被分配到所有桌面时，遮罩也出现在所有桌面。判断依据是窗口服务器报告的窗口所属桌面数，用的是私有接口，取不到时按"只属于一个桌面"处理。
- 否则遮罩只属于微信所在的桌面，切换桌面时两者一起滑入滑出；微信被移到别的桌面或进入全屏后，遮罩随之移到当前桌面。
- 遮罩不出现在调度中心（Mission Control）。

### 6.3 刷新时机

- **事件**：主窗口移动、缩放、最小化、销毁；微信隐藏、激活；前台应用切换；切换桌面；显示器配置变化。
- **拖动期间**：系统的窗口移动事件只在拖动结束时才发出，所以鼠标左键按下期间逐帧刷新，松开后再持续 0.3 秒。
- **兜底**：每 0.25 秒刷新一次，覆盖没有事件的变化。

### 6.4 校准

- 从菜单「校准遮罩位置…」进入，需要先解锁（校准时遮罩是半透明的，能看到列表，不能拿来绕过锁定）。可以拖动左、右、上三条边；「完成」保存，「取消」放弃，「恢复默认」回到默认布局。
- 布局保存为相对窗口的边距。移动或缩放窗口后不需要重新校准，只有在微信里拖动了列表栏宽度才需要。
- 两种遮挡方式各自保存校准结果，校准只修改当前方式的那一套。精准遮挡还没有校准过时，沿用整块遮挡的左边距和宽度，上边距取 0：整块遮挡的上边距可能被用来露出顶部的聊天，精准遮挡照搬的话会露出没有识别过的行。

### 6.5 锁定与解锁（M2）

- **解锁**：启动后处于锁定状态，遮罩中间有密码框（精准遮挡时在底部的遮挡条里）。点击密码框、输入密码后回车：正确则解锁并收起遮罩，错误则提示并清空。解锁只能通过遮罩上的密码框完成，菜单里没有解锁入口。
- **不抢焦点**：只有点击密码框时，遮罩才接收键盘输入；点遮罩的其他位置，不会抢走微信的键盘焦点。有其他窗口压住密码框时，密码框暂时隐藏。
- **输入显示**：密码框默认明文显示输入内容，右侧按钮可以切换为隐藏（显示为圆点）。程序记住用户最后一次的选择（配置 `hidePasswordInput`），下次锁定、重启后沿用。明文输入时只允许英文输入法，避免中文输入法把字母拼成候选词。
- **密码**：默认 `1234567890`。解锁后可以从菜单「修改密码…」设置新密码（输入两次，不再询问旧密码）。新密码保存为 PBKDF2-SHA256（10 万次迭代、16 字节随机盐、32 字节结果），不保存明文。
- **恢复默认密码**：菜单「恢复默认密码…」弹窗确认后，把密码改回 `1234567890`（删除配置里的 `password` 字段）。锁定时也能用；只改密码，不解锁也不锁定。
- **自动锁定**：主窗口关闭或最小化、微信被隐藏或退出时锁定；切换桌面不锁定。菜单「立即锁定」可以随时手动锁定。
- **区分"关闭"和"在其他桌面"**：两者在窗口服务器里都表现为不在屏上。关闭的窗口不属于任何桌面，在其他桌面上的窗口仍然属于那个桌面，靠这一点区分。查不到桌面信息时按"已关闭"处理，宁可多锁一次。

### 6.6 精准遮挡（v2）

遮挡方式有两种，在菜单里选择，默认整块遮挡，选择后立即生效并记住。遮挡方式只决定锁定时遮住哪里：解锁、自动锁定、修改和恢复密码、开机自启动的规则不变，锁定时也能切换。

- **露出条件**：遮挡方式为精准遮挡、已锁定、微信主窗口在当前桌面可见、有屏幕录制权限、白名单不为空。五个条件同时成立时才读取画面并露出白名单行，否则整块遮住并停止读取。
- **白名单**：按聊天列表里显示的名称填写，有备注就填备注。菜单「编辑白名单…」打开编辑窗口，每行一个名称，保存时去掉首尾空白、空行和重复项。只在精准遮挡且解锁时可以编辑；进入锁定或切回整块遮挡时编辑窗口关闭，未保存的修改丢弃。切到精准遮挡而名单为空时，如果已解锁就自动打开编辑窗口。
- **名称匹配**：去掉表情符号和首尾空白后完全一致才算匹配，只是包含不算；重名的行都露出。识别结果以省略号结尾（名称太长被截断）时，名单名称以省略号之前的文字开头也算，这段文字至少 2 个字符；末尾连续的 `.`、`…`、`⋯`、`•`、`·` 都按省略号处理。识别不出或匹配不上的行保持遮住。
- **读取画面**：每 0.2 秒取一张图，只截微信主窗口、裁到列表栏（不含底部遮挡条），按屏幕的原生分辨率取。不开持续的截图流：系统会给被持续截取的窗口打上紫色的共享标记。
- **变化检测**：把图切成 8 pt 高的水平条，每条横向分成 48 格，记录每格的亮度相对这一条底色（各格亮度的中位数）的偏差。与基准帧相比，一条里偏差变化超过 20 的格多于 3 个，就算内容变化；基准帧是最近一次判为变化的那张图。悬停只让整行底色小幅变化，每格偏差的变化不会超过底色的变化，所以不算；选中行的底色变化很大，按内容变化处理。
- **先遮后露**：内容一变化，已露出的行全部盖住（上限 0.3 秒，实际最坏约 0.27 秒）。变化之后第一张没有变化的图视为画面稳定，直接用这张图识别；识别完成且期间没有新的变化才露出，否则结果丢弃。在露出的行上滚动时，滚轮事件一到就盖住。识别超过 2 秒放弃，1 秒后重试。点击白名单行照常生效，但选中会让已露出的行盖住再露出一次。
- **行切分**：识别出的文字框里，左边缘对齐"正文左边界"的是名称和预览；时间、头像上的角标不对齐，不参与。上边缘相距较远的文字框分属不同的行，每行第一个框是名称。行高取相邻名称间距的中位数。带区以文字块为中心，上下各内缩 2 pt，横向覆盖整个列表栏。
- **窗口移动与缩放**：露出的带区按窗口坐标保存，窗口移动时直接跟着走；窗口大小变化时先盖住，再重新识别。
- **权限**：屏幕录制权限只在切到精准遮挡时申请。没有权限、权限被收回或读取画面失败时，遮挡方式保持不变但整块遮住，菜单提示"精准遮挡需要屏幕录制权限"并提供授权入口，每 5 秒重试一次。
- **隐私**：画面只在内存中处理，只保留最近一张，不保存、不联网。日志只记录取图次数、识别耗时、匹配行数，不记录识别出的文字。

### 6.7 开机自启动

- 菜单「开机自启动」勾选后，登录系统时自动启动 QuietChat；默认关闭。锁定时也能切换。
- 开关状态以系统登录项为准，不写入配置文件：用户也可以在系统设置里直接增删登录项，菜单每次打开都重新读取。macOS 用 `SMAppService.mainApp`。
- 系统要求用户在设置里另行允许，或登记失败时，弹窗说明并提供跳转到「系统设置 → 通用 → 登录项」的入口。

### 6.8 外观

- 菜单「外观」分组直接列出「跟随系统」「浅色模式」「深色模式」，按用户选择互斥勾选，默认跟随系统。锁定时也能切换。
- 选择后整个 QuietChat 界面立即生效：遮罩、密码框、校准控件、白名单窗口和弹窗使用同一外观，切换保留当前输入与校准草稿。
- macOS 通过 `NSApp.appearance` 统一应用：跟随系统为 `nil`，随系统变化自动更新；浅色为 `.aqua`，深色为 `.darkAqua`，固定外观不随系统变化。菜单每次打开时同步应用外观。
- 偏好保存为 `appearanceMode`，启动时在显示界面前应用。保存失败时本次仍生效并记录错误日志，下次启动读取最后成功保存的配置。

## 7. 配置

- **位置**：macOS 为 `~/Library/Application Support/QuietChat/config.json`；Windows 为 `%APPDATA%\QuietChat\config.json`。
- **格式**：见 `shared/config.schema.json`。写入时输出全部非空字段；读取时缺失字段取默认值，未知字段忽略。`password` 字段只在修改过密码后才出现。精准遮挡新增三个字段：`maskMode`（遮挡方式，缺失或取值未知时按整块遮挡）、`whitelist`（白名单，缺失时为空）、`preciseListColumn`（精准遮挡的校准结果，校准后才出现）；旧版本会忽略它们。
- **外观偏好**：`appearanceMode` 为 `system`、`light` 或 `dark`，缺失或未知字符串按 `system` 处理；旧版本忽略该字段，配置格式版本仍为 1。
- **损坏处理**：配置文件损坏时用默认配置继续运行，保证遮罩不会因此失效，下次保存时覆盖。
- **版本**：`schemaVersion` 只在不兼容的变化时递增。

## 8. 权限、签名与分发

- **权限**：整块遮挡只需要辅助功能权限，用于识别窗口、监听事件。精准遮挡还需要屏幕录制权限，用于读取聊天列表区域的画面，只在切到精准遮挡时申请。不联网。
- **不签名分发的代价**：首次打开要在「隐私与安全性」里允许；签名一变，辅助功能和屏幕录制的授权都会失效，需要重新授权。
- **开发期签名**：默认用本机临时签名。可以在 `macos/Configs/Local.xcconfig`（不提交）里指定固定的签名身份，重新编译后不必再授权。

## 10. 待验证问题

- 微信只属于一个桌面时，切换桌面、进入或退出全屏，遮罩能否和微信同步出现（6.2 的桌面归属依赖系统行为）。
- 关闭的主窗口是否不属于任何桌面（6.5 区分"关闭"和"在其他桌面"的依据）。实测：关闭、最小化、⌘H 时，微信会直接销毁主窗口的辅助功能元素，自动锁定走的是"没有主窗口"这条路，这个判断只是后备，还没被实际触发过。从未显示过的微信辅助窗口确实不属于任何桌面。
- 微信窗口变窄时，是否会自动收窄或隐藏列表栏。探测时把窗口缩到 630 宽，按 242 宽取图的区域右边出现了输入框的光标，说明列表栏变窄了；布局模型假设列表栏宽度固定，窄窗口下遮罩和取图区域会偏大。
- 精准遮挡的取图方式只在 macOS 26.5 上实测过。Apple 文档称截取单个窗口时不使用 `sourceRect`，macOS 14、15 上是否裁剪没有验证；不裁剪时识别不出名称，会一直整块遮住。
- 长时间定时取图是否会出现共享标记或录屏指示（探测只连续观察了 20 秒）。
- 浅色模式下悬停、选中的底色变化，以及名称的识别准确率。
- macOS 是否定期要求重新确认屏幕录制权限，以及届时的表现。
- 没有消息预览的行，名称不上下居中而是靠上，按文字块中心算出的带区会偏上约 7 pt（露出的是上一行底部的空白）。
