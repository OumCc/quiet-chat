# QuietChat 架构说明

> **摘要**：QuietChat 在微信电脑版窗口上方放一块遮罩，盖住聊天列表，只留几个快捷入口；输入密码才能看到全部聊天，关掉微信窗口后自动重新锁定。macOS 和 Windows 各用原生技术实现，共享本文定义的模块划分与行为规则，以及 `shared/` 下的配置格式。v1 分 M0–M3 四个阶段交付，每个阶段在真实环境验收通过后再进入下一阶段。

## 1. 目标与边界

- **目标**：打开微信时，不让无关的聊天、公众号先抢走注意力。定位是"加一点阻力"，不是安全锁。
- **v1 范围**：整块遮住聊天列表；遮罩上放快捷入口；输入密码解锁；关闭微信窗口后自动锁定。
- **不做**：注入或修改微信进程，读取聊天内容，联网。
- **可以接受的绕过**：⌘F 搜索、点通知跳转、独立聊天窗口、通讯录、直接退出 QuietChat。

## 2. 已验证的前提

| 结论 | 依据 | 影响 |
|---|---|---|
| 微信 4.x 界面基于 Qt（窗口类 `QNSWindow`）。辅助功能接口只暴露窗口本身和三个窗口按钮，读不到聊天列表 | Accessibility Inspector 检查（微信 4.1） | 窗口位置和事件用辅助功能接口获取；列表内容只能靠截图识别（v2） |
| 不需要任何权限，窗口服务器（CGWindowList）就能读到微信各窗口的外框、层级和是否在屏。微信进程同时有十来个 layer 0 窗口（提示框、条状辅助窗口等） | 本机实测 | 主窗口要靠辅助功能接口识别；微信自己的其他窗口不当作遮挡 |
| Apple Vision OCR 能认出列表里的聊天名称（真实深色截图 6/6）。置顶行和普通行的底色可以区分（`#3B3B3E` / `#2F2F30`） | `tools/probe/wechat_list_probe.swift` | v2 的精准遮挡可行 |

## 3. 平台策略

各平台原生实现，不用跨平台 UI 框架，理由见 [ADR-0001](adr/0001-native-per-platform.md)。两端共享：

- **模块划分与行为规则**：本文第 5、6 节。两端使用相同的模块名和语义。
- **配置格式**：`shared/config.schema.json`。两端的测试都要校验自己的配置模型与它一致。
- **测试样本**：`shared/fixtures/`，v2 引入截图识别时建立。

## 5. 模块

| 模块 | 职责 | macOS | Windows（规划） |
|---|---|---|---|
| Core | 纯逻辑：坐标换算、列表栏布局、遮罩决策、主窗口挑选、配置模型。不依赖界面和系统接口 | `QuietChatCore`（SwiftPM） | `QuietChat.Core`（.NET 类库） |
| WindowTracking | 找到微信主窗口，产出 `WindowSnapshot`；窗口可能变化时触发刷新 | 辅助功能（AXObserver）+ CGWindowList | SetWinEventHook + DWM 窗口外框 |
| Masking | 按 `MaskDecision` 显示、移动或收起遮罩；校准 | 不激活本应用的浮动 NSPanel | 置顶的分层窗口 |
| Lock（M2） | 锁定状态机、密码校验、自动锁定 | — | — |
| QuickEntry（M3） | 快捷入口跳转 | CGEvent 模拟按键 | SendInput |
| App | 菜单栏（托盘）、权限引导、读写配置、组装各模块 | NSStatusItem | NotifyIcon |

模块之间只通过 Core 定义的值类型交换数据：WindowTracking 产出 `WindowSnapshot`，Masking 执行 `MaskPlanner.decide` 返回的 `MaskDecision`。

## 6. 行为规则

### 6.1 遮罩几何

- 列表栏矩形：窗口外框左上角偏移 (`leftInset`, `topInset`)，宽 `width`，向下延伸到窗口底边，结果裁剪到窗口内。
- 其他应用的普通窗口（层级 0、可见）压在微信主窗口之上时，把它和列表栏重叠的部分从遮罩上挖掉（开洞），让给上层窗口。微信自己的其他窗口不开洞。
- 总原则：**宁可多遮，不漏出**。

### 6.2 显示规则

| 微信主窗口 | 遮罩 |
|---|---|
| 在当前桌面可见 | 显示在列表栏上 |
| 最小化、微信被隐藏或退出 | 收起 |
| 不在当前桌面，遮罩在当前桌面 | 收起（窗口被关闭或移走了） |
| 不在当前桌面，遮罩也不在当前桌面 | 保持不动（两者都在另一个桌面，切回去时一起出现） |

遮罩始终处于浮动层级，所以微信被点到最前时也盖不过它。

### 6.3 刷新时机

- **事件**：主窗口移动、缩放、最小化、销毁；微信隐藏、激活；前台应用切换；切换桌面；显示器配置变化。
- **拖动期间**：系统的窗口移动事件只在拖动结束时才发出，所以鼠标左键按下期间逐帧刷新，松开后再持续 0.3 秒。
- **兜底**：每 0.25 秒刷新一次，覆盖没有事件的变化。

### 6.4 校准

- 从菜单「校准遮罩位置…」进入。可以拖动左、右、上三条边；「完成」保存，「取消」放弃，「恢复默认」回到默认布局。
- 布局保存为相对窗口的边距。移动或缩放窗口后不需要重新校准，只有在微信里拖动了列表栏宽度才需要。

### 6.5 锁定与解锁（M2，待实现）

- 启动后默认锁定。在遮罩上输入密码，正确则收起遮罩。
- 默认密码 `1234567890`。用户修改后保存 PBKDF2-SHA256 哈希和随机盐，不保存明文。
- 自动锁定：主窗口关闭或最小化、微信隐藏或退出时锁定；切换桌面不锁定。

### 6.6 快捷入口（M3，待实现）

- 用户在设置中编辑聊天名称，预计 5 个左右。
- 点击后：激活微信 → ⌘F → 粘贴名称 → 回车。执行前保存剪贴板，结束后恢复。
- 前提（待确认）：微信搜索后按回车能直接打开第一个结果。

## 7. 配置

- **位置**：macOS 为 `~/Library/Application Support/QuietChat/config.json`；Windows 为 `%APPDATA%\QuietChat\config.json`。
- **格式**：见 `shared/config.schema.json`。写入时输出全部字段；读取时缺失字段取默认值，未知字段忽略。
- **损坏处理**：配置文件损坏时用默认配置继续运行，保证遮罩不会因此失效，下次保存时覆盖。
- **版本**：`schemaVersion` 只在不兼容的变化时递增。

## 8. 权限、签名与分发

- **权限**：v1 只需要辅助功能权限，用于识别窗口、监听事件，M3 还要用它模拟按键。v2 再加屏幕录制权限，用于截图识别。不联网。
- **不签名分发的代价**：首次打开要在「隐私与安全性」里允许；签名一变，辅助功能授权就失效，需要重新授权。
- **开发期签名**：默认用本机临时签名。可以在 `macos/Configs/Local.xcconfig`（不提交）里指定固定的签名身份，重新编译后不必再授权。

## 10. 待验证问题

- 切换桌面、进入或退出全屏时，遮罩能不能和微信同步出现（6.2 的桌面判断依赖系统行为）。
- 微信主窗口"被关闭"和"在其他桌面"，在窗口服务器里都表现为不在屏上；M2 的自动锁定需要区分这两种情况。
- 微信窗口变窄时，是否会自动收窄或隐藏列表栏。
- 微信 ⌘F 搜索后回车，能否直接打开目标聊天（M3 的前提）。
