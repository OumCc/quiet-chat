# QuietChat 架构说明

> **摘要**：QuietChat 在微信电脑版窗口上方放一块遮罩，盖住聊天列表；输入密码才能看到全部聊天，关掉微信窗口后自动重新锁定。遮挡方式有两种：整块遮住，或者在不透明遮罩上显示白名单快捷入口。普通聊天自动搜索回车，文件传输助手准备搜索后由用户点击微信「功能」卡片。macOS 和 Windows 各用原生技术实现，共享本文定义的模块划分与行为规则，以及 `shared/` 下的配置格式。M0–M2 的窗口与锁定能力保留，原精准截图链路由快捷入口替换；实现和验收顺序见本次 OpenSpec change。

## 1. 目标与边界

- **目标**：打开微信时，不让无关的聊天、公众号先抢走注意力。定位是"加一点阻力"，不是安全锁。
- **v1 范围**：整块遮住聊天列表；输入密码解锁；关闭微信窗口后自动锁定。
- **快捷入口范围**：按配置顺序显示静态按钮，原聊天列表保持不透明；点击后通过键盘搜索进入普通聊天，或为文件传输助手准备手动选择。
- **不做**：注入或修改微信进程、联网、窗口截图、OCR、搜索结果解析、鼠标坐标自动点击、剪贴板兜底或聊天身份确认。
- **可以接受的绕过**：⌘F 搜索、点通知跳转、独立聊天窗口、通讯录、直接退出 QuietChat、锁定时先恢复默认密码再解锁。

## 2. 已验证的前提

| 结论 | 依据 | 影响 |
|---|---|---|
| 微信 4.x 界面基于 Qt（窗口类 `QNSWindow`）。辅助功能接口只暴露窗口本身和三个窗口按钮，读不到聊天列表 | Accessibility Inspector 检查（微信 4.1） | 辅助功能只用于窗口跟踪和焦点身份核对，不假设能读到列表或搜索结果 |
| 不需要任何权限，窗口服务器（CGWindowList）就能读到微信各窗口的外框、层级和是否在屏。微信进程同时有十来个 layer 0 窗口（提示框、条状辅助窗口等） | 本机实测 | 主窗口要靠辅助功能接口识别 |
| 转发等弹窗是微信单独的 layer 0 窗口，压在主窗口之上，但不在辅助功能窗口列表里；弹出时主窗口变暗由主窗口自己绘制，没有单独的蒙层窗口。主窗口显示时，微信的辅助窗口都不在屏。右键菜单在 layer 21，本来就高于遮罩 | 本机实测（微信 4.1） | 微信自己的窗口也当作遮挡、开洞让出；弹窗只能靠窗口服务器识别 |
| 微信 4.1.13（269602）、macOS 26.5 的键盘路径通过门禁：普通聊天完整搜索回车，文件传输助手填词后手动选择，卡片上下排列均覆盖 | [change research](../openspec/changes/replace-precise-masking-with-whitelist-shortcuts/research.md)，2026-10-10 V-001～V-003 | 历史门禁时序记录保留；6.6 提供常规响应速度设置，实际效果由用户实测；自动导航曾错误提交网络建议，已停止使用 |
| 搜狗拼音中文模式下 CGEvent Unicode 保留中文、英文、长名称、组合表情，并完整替换旧词；搜索准备后的 AX 搜索控件焦点仍为 unavailable | 同上 | 不改剪贴板；程序只能核对进程和主窗口，不能声称检测到搜索就绪或打开成功 |

## 3. 平台策略

各平台原生实现，不用跨平台 UI 框架，理由见 [ADR-0001](adr/0001-native-per-platform.md)。两端共享：

- **模块划分与行为规则**：本文第 5、6 节。两端使用相同的模块名和语义。
- **配置格式**：`shared/config.schema.json`。两端的测试都要校验自己的配置模型与它一致。
- **测试契约**：配置兼容、名单整理、操作编号、几何、密码与锁定在纯逻辑包验证；真实聊天身份和界面交接由用户实测确认，不写入操作日志。

## 5. 模块

| 模块 | 职责 | macOS | Windows（规划） |
|---|---|---|---|
| Core | 纯逻辑：坐标换算、列表栏布局、遮罩决策、主窗口挑选、配置模型、名单整理和快捷操作编号。不依赖界面和系统接口 | `QuietChatCore`（SwiftPM） | `QuietChat.Core`（.NET 类库） |
| WindowTracking | 找到微信主窗口，产出 `WindowSnapshot`；监听变化、有界聚焦与身份核对 | 辅助功能（AXObserver）+ CGWindowList | SetWinEventHook + DWM 窗口外框 |
| Masking | 按 `MaskDecision` 显示、移动或收起遮罩；校准、静态按钮与密码控件 | 不激活本应用的浮动 NSPanel | 置顶的分层窗口 |
| Lock（M2） | 锁定状态、密码校验、自动锁定 | Core 的 `LockState`、`PasswordVerifier`（CommonCrypto），遮罩上的密码框 | 同样的 Core 类型，`Rfc2898DeriveBytes.Pbkdf2` |
| Shortcuts | 一次可取消的完整键盘搜索；忙碌禁用、阶段核对、错误及手动选择反馈 | `WeChatShortcutController` + CGEvent | 待实现 |
| App | 菜单栏（托盘）、权限引导、读写配置、白名单编辑、组装各模块 | NSStatusItem | NotifyIcon |

模块之间只通过 Core 定义的值类型交换数据：WindowTracking 产出 `WindowSnapshot`，Masking 执行 `MaskPlanner.decide` 返回的 `MaskDecision`。`ShortcutOperationState` 只管理编号；`WeChatShortcutController` 处理系统事件，`AppDelegate` 核对当前模式、锁定、名单与目标。显示刷新不会启动搜索。原 Capture / Detection 及专用 Core 识别逻辑已退役，`tools/probe` 的历史探测文件保留，不进入应用运行时。

## 6. 行为规则

### 6.1 遮罩几何

- 列表栏矩形：窗口外框左上角偏移 (`leftInset`, `topInset`)，宽 `width`，向下延伸到窗口底边，结果裁剪到窗口内。
- 其他普通窗口（层级 0、可见）压在微信主窗口之上时，把它和列表栏重叠的部分从遮罩上挖掉（开洞），让给上层窗口。微信自己的窗口（转发等弹窗、独立聊天窗口）同样开洞。
- 两种方式都不为聊天名称开洞。快捷入口底部 56 pt 放密码框，上方按钮区独立滚动；按钮和反馈容器背景透明，与上层窗口洞相交时保守隐藏整个相关容器并禁用按钮，移开后恢复。密码控件继续按相交规则隐藏。
- 遮罩和洞一律向外取整到整点，校准结果也取整。小数坐标会在边缘留下半透明像素，看起来是一条细线，而且会挡住点击。
- 总原则：**宁可多遮，不漏出**。

### 6.2 显示规则

| 微信主窗口 | 遮罩 |
|---|---|
| 在当前桌面可见 | 显示在列表栏上 |
| 最小化、微信被隐藏或退出 | 收起 |
| 不在当前桌面，遮罩在当前桌面 | 收起（窗口被关闭或移走了） |
| 不在当前桌面，遮罩也不在当前桌面 | 保持不动（两者都在另一个桌面，切回去时一起出现） |

遮罩始终处于浮动层级，所以微信被点到最前时也盖不过它。

桌面归属：
- 微信主窗口被分配到所有桌面时，遮罩也出现在所有桌面。判断依据是窗口服务器报告的窗口所属桌面数，用的是私有接口，取不到时按"只属于一个桌面"处理。
- 否则遮罩只属于微信所在的桌面，切换桌面时两者一起滑入滑出；微信被移到别的桌面或进入全屏后，遮罩随之移到当前桌面。
- 遮罩不出现在调度中心（Mission Control）。

### 6.3 刷新时机

- **事件**：主窗口移动、缩放、最小化、销毁；微信隐藏、激活；前台应用切换；切换桌面；显示器配置变化。
- **拖动期间**：系统的窗口移动事件只在拖动结束时才发出，所以鼠标左键按下期间逐帧刷新，松开后再持续 0.3 秒。
- **兜底**：每 0.25 秒刷新一次，覆盖没有事件的变化。

### 6.4 校准

- 从菜单「校准遮罩位置…」进入，需要先解锁（校准时遮罩是半透明的，能看到列表，不能拿来绕过锁定）。可以拖动左、右、上三条边；「完成」保存，「取消」放弃，「恢复默认」回到默认布局。
- 布局保存为相对窗口的边距。移动或缩放窗口后不需要重新校准，只有在微信里拖动了列表栏宽度才需要。
- 两种遮挡方式各自保存校准结果，校准只修改当前方式的那一套。快捷入口还没有校准过时，沿用整块遮挡的左边距和宽度，上边距取 0，以遮住完整列表。

### 6.5 锁定与解锁（M2）

- **解锁**：启动后处于锁定状态，遮罩中间有密码框（快捷入口时在底部 56 pt 区域）。点击密码框、输入密码后回车：正确则解锁并收起遮罩，错误则提示并清空。解锁只能通过遮罩上的密码框完成，菜单里没有解锁入口。
- **不抢焦点**：只有点击密码框时，遮罩才接收键盘输入；明文和隐藏输入控件在用户点击时通过 AppKit 的 makeKey 取回键盘焦点，先取消未结束的搜索，保留密码草稿。点遮罩的其他位置，不会抢走微信的键盘焦点。有其他窗口压住密码框时，密码框暂时隐藏。
- **输入显示**：密码框默认明文显示输入内容，右侧按钮可以切换为隐藏（显示为圆点）。程序记住用户最后一次的选择（配置 `hidePasswordInput`），下次锁定、重启后沿用。明文输入时只允许英文输入法，避免中文输入法把字母拼成候选词。
- **密码**：默认 `1234567890`。解锁后可以从菜单「修改密码…」设置新密码（输入两次，不再询问旧密码）。新密码保存为 PBKDF2-SHA256（10 万次迭代、16 字节随机盐、32 字节结果），不保存明文。
- **恢复默认密码**：菜单「恢复默认密码…」弹窗确认后，把密码改回 `1234567890`（删除配置里的 `password` 字段）。锁定时也能用；只改密码，不解锁也不锁定。
- **自动锁定**：主窗口关闭或最小化、微信被隐藏或退出时锁定；切换桌面不锁定。菜单「立即锁定」可以随时手动锁定。
- **区分"关闭"和"在其他桌面"**：两者在窗口服务器里都表现为不在屏上。关闭的窗口不属于任何桌面，在其他桌面上的窗口仍然属于那个桌面，靠这一点区分。查不到桌面信息时按"已关闭"处理，宁可多锁一次。

### 6.6 白名单快捷入口

菜单只有「整块遮挡」「白名单快捷入口」两种方式，默认 full。切换立即生效并保存，锁定时也可切换；通用解锁、自动锁定、密码、外观及登录项规则继承原行为。

- **入口**：shortcuts、锁定、有效主窗口可见时，在当前遮罩上按名单顺序显示按钮，位置与微信列表滚动、消息重排无关。长标签可截断并提供完整提示，点击使用完整保存字符串。解锁、校准时隐藏按钮；空名单保留遮罩和密码控件。
- **名单**：填写完整搜索名称，有备注就填完整备注；只整理首尾空白、空项和重复项，保留顺序、内部空格、表情和标点。仅 shortcuts 且已解锁可编辑；锁定或切回 full 关闭编辑窗口并丢弃草稿，已解锁时首次空名单沿用编辑引导。
- **普通聊天**：按钮点击捕获名称、PID、主窗口 ID 和操作编号，结束遮罩输入焦点但保留密码草稿；只抬起跟踪的主窗口。真实前台 PID 和聚焦窗口确认后执行 ⌘F → 等待 → ⌘A → 等待 → 完整 CGEvent Unicode → 等待 → 一次回车。
- **文件传输助手**：整理后的名称恰为「文件传输助手」时执行相同搜索准备，随后结束任务、恢复入口并显示「请在微信点击『功能』中的文件传输助手」。不发方向键、Tab、回车或鼠标事件，不抢回焦点，不等待或检测人工选择。切走导致微信搜索隐藏时不自动重放，用户再次点击才重新开始。遮罩若妨碍原生卡片手动选择，必须停止相关验收并澄清，不能临时隐藏或解锁。
- **有界参数**：AX 单次调用 0.3 秒；主窗口激活请求后最多确认 1.5 秒；搜索打开、全选后、Unicode 后的当前基准均为 0 毫秒，用户已实测全零可用。历史门禁与速度试验记录保留在对应 change research 中。等待期间每 50 毫秒核对并使用可取消异步等待，允许主运行循环处理通知；零等待仍进入同一核对流程。固定等待总和不包括聚焦、系统调用或微信显示聊天的耗时，也不代表已检测到搜索框就绪。
- **响应速度菜单**：「编辑白名单…」之后的「白名单快捷入口响应速度」只在 shortcuts 方式可用，锁定时也可修改。「打开搜索」「全选旧搜索词」「等待搜到结果」各自按顺序提供零基准、对应的 75／25／250 毫秒预设及自定义；自定义上限独立保留 150／50／500 毫秒，修改一段保留其余两段。固定等待合计及「恢复基准（0 毫秒）」保留，恢复只将三段时序归零。配置成功保存后重启沿用；保存失败本次仍生效并记录错误，下次读取最后保存值。效果不佳时可尝试非零组合或自定义，详见 [常规速度设置设计](../openspec/changes/promote-whitelist-shortcut-timing/design.md)。
- **时序快照**：打开菜单及参数变更先取消旧搜索，选择本身不发送按键；下一次白名单点击捕获不可变 ShortcutTiming，每次开始记录三段整数，后续阶段沿用耗时日志。程序不自动识别搜索成功、调整参数或重放，日志中的 finished 仅表示指令序列结束，真实聊天结果由用户观察。
- **单次与取消**：一次只接受一个操作，不排队或重试。模式切换、解锁、名单更新、detach、退出、目标隐藏/关闭或主窗口身份改变取消操作；确认焦点后离开前台或切到独立窗口也停止。用户点击密码框或打开 QuietChat 菜单时，本应用主动通知取消，补足非激活界面的输入接管。发送前再次核对权限、操作编号和焦点，取消使旧编号失效，旧任务完成不能清除新任务。
- **反馈与边界**：忙碌时禁用入口，密码解锁仍可用。普通聊天指令结束清除处理中提示；文件传输助手显示手动选择提示。窗口无法确认、权限不足等可检测失败提供短反馈，不弹出身份已验证的成功通知。重名、多匹配、无结果及客户端变化不自动消歧；日志只含阶段、三段等待值、耗时、错误码。

### 6.7 开机自启动

- 菜单「开机自启动」勾选后，登录系统时自动启动 QuietChat；默认关闭。锁定时也能切换。
- 开关状态以系统登录项为准，不写入配置文件：用户也可以在系统设置里直接增删登录项，菜单每次打开都重新读取。macOS 用 `SMAppService.mainApp`。
- 系统要求用户在设置里另行允许，或登记失败时，弹窗说明并提供跳转到「系统设置 → 通用 → 登录项」的入口。

### 6.8 外观

- 菜单「外观」分组直接列出「跟随系统」「浅色模式」「深色模式」，按用户选择互斥勾选，默认跟随系统。锁定时也能切换。
- 选择后整个 QuietChat 界面立即生效：遮罩、密码框、校准控件、白名单窗口和弹窗使用同一外观，切换保留当前输入与校准草稿。
- macOS 通过 `NSApp.appearance` 统一应用：跟随系统为 `nil`，随系统变化自动更新；浅色为 `.aqua`，深色为 `.darkAqua`，固定外观不随系统变化。菜单每次打开时同步应用外观。
- 偏好保存为 `appearanceMode`，启动时在显示界面前应用。保存失败时本次仍生效并记录错误日志，下次启动读取最后成功保存的配置。

## 7. 配置

- **位置**：macOS 为 `~/Library/Application Support/QuietChat/config.json`；Windows 为 `%APPDATA%\QuietChat\config.json`。
- **格式与兼容**：见 `shared/config.schema.json`，版本保持 1。缺失字段取默认值，未知字段忽略；`password` 仅修改密码后出现。`maskMode` 新输出 full / shortcuts，旧 precise 读取为 shortcuts，未知字符串回退 full。兼容加载不立即改写原文件，后续正常保存输出当前方式。名单、密码、输入显示偏好、外观和两种校准保留。
- **响应速度**：`shortcutTiming` 保存 `searchOpenMs`、`selectAllMs`、`resultsMs` 三个整数，范围分别为 0...150、0...50、0...500，默认全零。`shortcutTimingVersion` 当前为整数 1；缺失、类型错误或不为 1 时，旧速度设置整组归零，保留其他有效配置，读取不改写原文件。正常保存时写入当前标记，此后有效选择重启沿用；标记有效时，缺失、错误类型或越界阶段独立归零，整个时序对象缺失或无效时回退整组零值。旧程序忽略速度版本标记，配置总版本仍为 1。
- **历史键**：`listColumn` 保存整块遮挡布局；`preciseListColumn` 保留历史名字，保存快捷入口独立校准。缺失时取 listColumn 的 leftInset / width，topInset=0；未校准时不编码该可选字段。旧程序读 shortcuts 会回退 full，名单和历史布局键仍可读。
- **外观偏好**：`appearanceMode` 为 `system`、`light` 或 `dark`，缺失或未知字符串按 `system` 处理；旧版本忽略该字段，配置格式版本仍为 1。
- **损坏处理**：配置文件损坏时用默认配置继续运行，保证遮罩不会因此失效，下次保存时覆盖。
- **版本**：`schemaVersion` 只在不兼容的变化时递增。

## 8. 权限、签名与分发

- **权限**：窗口跟踪使用 AXIsProcessTrusted；快捷入口开始与每组事件前另核对 CGPreflightPostEventAccess。缺失时沿用辅助功能设置入口，并按需请求事件合成访问，不发送事件。两种方式均不申请录屏或输入监听，不截图、不联网；旧录屏权限可由用户撤销，不影响新方式。
- **不签名分发的代价**：首次打开要在「隐私与安全性」里允许；签名一变，辅助功能和键盘合成访问可能失效，需要重新授权。
- **开发期签名**：默认用本机临时签名。可以在 `macos/Configs/Local.xcconfig`（不提交）里指定固定的签名身份，重新编译后不必再授权。

## 10. 待验证问题

- 微信只属于一个桌面时，切换桌面、进入或退出全屏，遮罩能否和微信同步出现（6.2 的桌面归属依赖系统行为）。
- 关闭的主窗口是否不属于任何桌面（6.5 区分"关闭"和"在其他桌面"的依据）。实测：关闭、最小化、⌘H 时，微信会直接销毁主窗口的辅助功能元素，自动锁定走的是"没有主窗口"这条路，这个判断只是后备，还没被实际触发过。从未显示过的微信辅助窗口确实不属于任何桌面。
- 微信窗口变窄时，列表栏可能自动收窄；布局模型保留固定校准宽度，需要用户按实际布局调整，未新增自适应识别。
- 键盘路径尚未在其他微信版本或更早 macOS 上验证；更新后的搜索行为、不同输入法需要重新验证。
- 搜索控件、结果身份不可观察；重名或多匹配需要用户选择适合既定搜索回车路径的完整名称，或者按原规则解锁处理。
