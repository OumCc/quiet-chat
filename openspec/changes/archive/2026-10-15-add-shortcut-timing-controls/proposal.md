# 变更提案

## 审阅摘要

- 为什么现在做：700 毫秒版本已得到用户正面反馈，需要减少反复编译才能试不同时间的成本。
- 目标结果：在菜单中独立调整三个等待阶段，支持人工二分、自定义整数毫秒及重启恢复。
- 边界：只调整键盘搜索时序，不自动判定打开成功、不改变目标选择和锁定规则。
- 验收：预设、自定义、恢复基准、保存及操作快照通过检查；最终微信组合由用户实测。
- 风险：零或较短等待可能导致错误落点；二分结果只代表本机已覆盖样本，不承诺响应严格单调。

## 已确认变化

1. 增加「快捷入口速度（测试）」菜单，按阶段提供预设及自定义值，只在 shortcuts 方式下可用。
2. 默认沿用 150／50／500 毫秒；每阶段允许 0 到基准之间的整数，一键恢复全部基准。
3. 保存选择，旧配置缺失或无效新值按阶段回退；格式版本仍为 1。
4. 参数变更取消旧搜索，下一次主动点击捕获整组快照；日志记录时序及阶段耗时。

## 范围

包含菜单与自定义输入、配置兼容、搜索时序注入、聚焦测试及使用说明。排除自动微信实测、自动结果判定、结果识别、全局键盘绑定、联网、新权限和 Windows 实现。

## 能力清单

### 新增能力

- `shortcut-timing-controls`：分阶段时序菜单、持久化兼容、操作快照及人工二分测试边界。

### 修改能力

没有已发布的基线规格，本次使用 ADDED Requirements。历史快捷入口 change 的实测记录保留；其「参数不作为配置」限制在本次明确授权的测试菜单范围内被替代。

## 影响与证据

菜单、应用装配、纯逻辑配置及搜索控制器需增加时序契约；共享 Schema 与字段一致性测试同步。没有后端 API 或新增依赖。

依据 [research.md](research.md) S-02～S-04；Q-001 分阶段、Q-002 持久化、Q-003 自定义均已确认，Q-004 的历史约束已明确处理。当前菜单与焦点取消机制作为保留基线。
