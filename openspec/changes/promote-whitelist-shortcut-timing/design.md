# 技术设计

## 审阅摘要

- 方案：零基准、独立范围与固定预设；通过配置内版本标记区分升级前后的速度设置。
- 边界：复用原生菜单、参数快照和原子保存，只更新当前说明及相关测试。
- 兼容：`schemaVersion` 仍为 1，旧设置全部归零但读取不写文件；后续正常保存标记。
- 验证：Core 与迁移／Schema 回归，替身菜单与对话框检查，Debug 构建和严格规格校验。
- 风险与待确认：全零效果受微信响应影响，保留非零组合与原上限；无未决事项。

## 当前与目标流程

[CODE] 当前 `TimingStage.maximum` 从基准取值，预设逐次减半；`ShortcutTiming` 的默认、回退和范围绑定。目标将三者分离，菜单只保留指定选项。

目标加载流程：读取 JSON → 检查 `shortcutTimingVersion` → 无有效标记时速度整组归零／标记为 1 时按原字段解码并独立归零 → 保留其他配置 → 正常保存时写入当前标记。加载不执行保存。

菜单流程沿用：打开菜单取消旧操作 → 选择单段／恢复 → AppDelegate 核对 shortcuts、取消并保存 → 下次主动点击捕获完整时序。搜索的按键、等待核对、文件传输助手交接不修改。

## 接口与兼容契约

- `ShortcutTiming` 的三个只读 Int 字段、Codable 形状及 `totalMs` 保留；公开三个阶段的固定范围供菜单和构造校验使用。省略参数、解码缺失／错误、越界回退均为零。
- `AppConfig` 追加只读 `shortcutTimingVersion` 与当前版本常量 1；初始化及成功解码实例均携带当前标记，不提供外部修改标记的入口。
- 解码使用原 JSON 标记判定：只有能解码为整数 1 时读取旧的时序对象；缺失、错误类型或其他值统一忽略整个旧时序并采用全零。标记有效时，时序对象无效回退整组，阶段错误独立归零。
- 编码始终输出标记 1；正常原子保存后再加载保留非零选择。旧程序忽略新增字段；历史版本写回并丢弃标记后，再升级会按未迁移配置归零。
- Schema 追加标记的整数类型、const 1、default 1；时序三个默认及对象默认为零，maximum 保留原值。字段一致性测试分别检查默认与上限。

## 菜单与错误状态

- 当前值子菜单及总和保留，预设为 `[0, 75]`／`[0, 25]`／`[0, 250]`；零标为基准，非零不再被误标为基准。
- 非预设有效值显示并勾选自定义；预填、整数范围错误原框重试、取消不修改值沿用现有实现。
- full 时父菜单禁用并由动作及 AppDelegate 再核对；shortcuts 锁定时仍可调整，不改变锁定状态。
- 恢复项从 `ShortcutTiming.baseline.totalMs` 生成文案并恢复全零。保存失败本次仍生效并记录错误，沿用原策略。

## 说明与验证

README 删除人工速度下限试验流程，说明打开搜索后、全选旧词后、输入名称后三个固定等待的用途；效果不佳时先尝试 75／25／250，再在原范围分别自定义；恢复基准重新归零。架构文档同步当前规则，历史实测及 OpenSpec 保留。

Core 测试覆盖零默认、非零预设、原上限与独立回退；迁移测试使用临时文件，覆盖旧基准／预设／自定义、标记缺失或非法、其他设置与读取不改文件，以及保存非零后重载。菜单检查用替身 delegate 编译实际菜单源码，不发送微信事件；对话框检查覆盖预填、合法上限、非法输入与取消。使用本地 Swift/Xcode，关闭自动解析，产物写入 `/private/tmp`。
