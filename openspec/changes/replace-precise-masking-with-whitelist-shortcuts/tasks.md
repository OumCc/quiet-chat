# 实施任务

## 审阅摘要

- 实施目标：落实 masking-mode、chat-whitelist、whitelist-shortcuts，使用静态按钮与纯键盘打开路径替换原精准遮挡。
- 依赖顺序：本机技术门禁 → 配置兼容与操作状态 → 主窗口聚焦和按键协调 → 遮罩 UI → 装配与旧链路退役 → 文档 → 构建和回归。
- 完成定义：三项技术门禁及全部任务完成，两条打开路径和取消行为实测通过，原功能回归通过，运行时没有截图/OCR/录屏授权依赖；旧配置不丢数据。
- 最终验证集合：Swift 现有包测试；Xcode Debug/Release 构建和启动冒烟；支持微信版本的交互验收；整块遮挡/窗口避让/锁定/外观/独立校准回归；OpenSpec status 与严格校验。
- 当前状态：仅方案产物完成，以下实施任务均未执行。实施需用户明确授权；V-001～V-003 未通过时不推进生产按键路径，也不自行引入其他技术路线。

## 1. 通过键盘路径技术门禁

- [ ] 1.1 在用户本机的目标微信版本验证 research V-001：搜索「文件传输助手」，确定从已知初始选中状态到「功能」卡片的稳定方向键序列；覆盖重复搜索及网络建议状态变化 — 验证：导航后回车打开真实聊天，不提交网络建议；记录版本、起始状态和确切序列，不以图片中的数量推定按键次数。
- [ ] 1.2 验证 V-002：使用 CGEvent Unicode 输入中文、英文、长名称、表情名称，覆盖中文输入法及已有搜索词 — 验证：搜索文字与完整名称一致、不落入聊天编辑框、剪贴板内容未改写；不通过时停止，不静默改用粘贴。
- [ ] 1.3 验证 V-003：从遮罩按钮及密码框焦点交接到微信主窗口，覆盖已有搜索、独立微信窗口、用户中途切换前台；确定聚焦、搜索及结果等待的有限参数 — 验证：普通聊天路径能重复打开目标，前台/主窗口失效后不继续文字或提交；记录搜索控件焦点可观察性以及仅有时序等待的限制。
- [ ] 1.4 将 1.1～1.3 的实测证据和参数补充到本变更 research / design，确认当前版本的键盘路线达到验收 — 验证：V-001～V-003 均有结果，无猜测导航、未授权兜底或未决产品分支；失败时保持本组未完成并回到需求澄清。
